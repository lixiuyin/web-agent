**What the Playwright `Page` class represents**

Per the official Playwright for Python API reference page (title: "Page | Playwright Python"):

- **Core definition:** "Page provides methods to interact with a single tab in a `Browser`, or an extension background page in Chromium. One `Browser` instance might have multiple `Page` instances." In other words, `Page` is the API object that models **one browser tab (one document/frame tree)** — or, in Chromium, a single extension background page — and it is the main workhorse class through which a test/script drives that tab.
- **Lifecycle/creation:** Pages are not constructed directly by users; they are obtained from a `Browser` (e.g. `browser.new_page()` / `browser.new_browser_cdp_session()`-style workflows) or from a `BrowserContext`, and the same `Browser` can host many concurrent `Page` objects. The documented example on the page creates a page, navigates it to a URL, and then saves a screenshot (shown in both Sync and Async API tabs, e.g. `from playwright.sync_api import sync_playwright, Playwright` → `browser = webkit.launch()` → page → `page.goto(...)` → `page.screenshot(...)`).
- **Responsibilities exposed by the class:** navigation (`goto`, reload/back/forward), input/interaction with elements (click/type/hover, plus locator handling such as `add_locator_handler` listed in the page's table of contents), waiting for conditions/navigation, reading page state (content, titles, URLs, screenshots/PDFs), network-related behavior (requests/responses, routing, mocking), dialogs/downloads, JavaScript execution, and keyboard/mouse/touchscreen helpers.
- **Event model:** "The `Page` class emits various events (described below) which can be handled using any of Node's native `EventEmitter` methods, such as `on`, `once` or `removeListener`." In the Python binding this corresponds to subscribing with `page.on(...)` / `page.once(...)` for events such as console messages, page errors, requests/responses, dialogs, downloads, and popup/close.
- **Related class names cross-linked in the intro:** the page links to "extension background page" and to `Page`/`Browser`/`APIRequest` class references, situating `Page` inside the layered object model `Playwright → BrowserType → Browser → BrowserContext → Page → Frame/Locator`.
