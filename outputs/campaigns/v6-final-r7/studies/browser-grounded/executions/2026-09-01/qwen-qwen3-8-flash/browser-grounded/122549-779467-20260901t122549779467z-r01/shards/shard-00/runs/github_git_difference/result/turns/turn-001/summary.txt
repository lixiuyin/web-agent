**The distinction, explained:**
- **Git** is the underlying **open-source version-control software** — the tool that runs on your own machine and tracks changes to files/history (commits, branches, diffs). It is a standalone program, not owned by or dependent on GitHub; GitHub's own docs treat it as separate software that you install and configure (see the sibling "Git basics"/"Set up Git" content, which links out to git-scm.com for downloading Git).
- **GitHub** is a **hosted platform/service for building software** that is *based on* Git. It adds the networked collaboration layer on top of Git: repositories hosted in the cloud, plus planning and delivery workflows across the whole software development life cycle (repositories, pull requests/review, and other SDLC tooling described on this page).
- So the relationship is **tool vs. platform**: Git = the version-control engine; GitHub = the platform built on Git that stores/shares that work and supports the surrounding collaboration and delivery workflow. You can use Git without GitHub, but GitHub cannot exist without Git.
