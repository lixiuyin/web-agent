**NAME:** git — the stupid content tracker

**SYNOPSIS (as reported on the official git(1) manual page):**

```
git [-v | --version] [-h | --help] [-C <path>] [-c <name>=<value>]
    [--exec-path[=<path>]] [--html-path] [--man-path] [--info-path]
    [-p | --paginate | -P | --no-pager] [--no-replace-objects] [--no-lazy-fetch]
    [--no-optional-locks] [--no-advice] [--bare] [--git-dir=<path>]
    [--work-tree=<path>] [--namespace=<name>] [--config-env=<name>=<envvar>]
    <command> [<args>]
```

Reading of the synopsis: these are the options recognized *before* the subcommand (`<command> [<args>]`) — version/help (`-v`/`--version`, `-h`/`--help`), working-directory and config overrides (`-C <path>`, `-c <name>=<value>`, `--config-env=<name>=<envvar>`), path reporters (`--exec-path[=<path>]`, `--html-path`, `--man-path`, `--info-path`), pager control (`-p`/`--paginate`, `-P`/`--no-pager`), and repository-mode flags (`--no-replace-objects`, `--no-lazy-fetch`, `--no-optional-locks`, `--no-advice`, `--bare`, `--git-dir=<path>`, `--work-tree=<path>`, `--namespace=<name>`).
