**Role of Playwright locators (per the official Playwright for Python API reference)**

**Definition / core role:** The Locator class page states verbatim: *"Locators are the central piece of Playwright's auto-waiting and retry-ability. In a nutshell, locators represent a way to find element(s) on the page at any moment. A locator can be created with the `page.locator()` method."*

So a locator's role is to be a **lazy, reusable description of how to find elements**, not a captured element handle:

1. **Deferred resolution ("at any moment").** Creating a locator performs no DOM lookup and does not fail if nothing matches yet. The selector is re-evaluated each time the locator is used, so it always resolves against the *current* page state — this is what makes it safe across navigation, re-renders, and dynamic DOM changes (unlike a one-time `query_selector()` element handle that can go stale).
2. **The backbone of auto-waiting and retry-ability.** Every action (`click`, `fill`, `check`, `hover`, ...) and every query (`text_content`, `count`, `all_inner_texts`, `is_visible`, ...) re-resolves the locator and waits/polls until the element satisfies the required preconditions (attached, visible, stable, enabled, editable, receives events) or the timeout elapses. That is why you generally do not need `sleep()`/manual waits in Playwright tests.
3. **A uniform API surface for interacting with and asserting on elements.** The class exposes the action methods plus matching/refinement APIs — e.g. `filter()`, `nth()`, `first()`, `last()`, `and_()`, `or_()`, `locator()`, `get_by_role/text/label/placeholder/alt_text/title/test_id` (via page/frame), and `all()` which, per the docs, *"When the locator points to a list of elements, this returns an array of locators, pointing to their respective elem[ents]"* (Added in: v1.29). This lets you model lists of rows/items as locators rather than materializing elements.
4. **Frame, shadow DOM and page-object abstraction.** A locator carries the selector plus its scope (page/frame/another locator), so it transparently pierces shadow roots and works across frames, making it the natural building block for page-object models.
5. **Web-first assertions.** Locators are the input to `expect(locator).to_be_visible()`, `to_have_text()`, etc., so the same retry logic powers assertions.
