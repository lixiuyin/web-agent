**What `git status` shows (per the official Git manual)**

**Name / purpose:** `git-status - Show the working tree status` (NAME section). Synopsis: `git status [<options>] [--] [<pathspec>…​]`.

**Core answer — the DESCRIPTION section states it displays paths in three categories:**
1. **Paths that have differences between the index file and the current HEAD commit** — i.e. staged changes. The manual notes “The first are what you would commit by running `git commit`.”
2. **Paths that have differences between the working tree and the index file** — i.e. unstaged local modifications.
3. **Paths in the working tree that are not tracked by Git (and are not ignored by `gitignore[5]`)** — i.e. untracked files.

For categories 2 and 3, the manual says these “are what you could commit by running `git add` before running `git commit`.” In other words, `git status` reports the state of the three Git areas (HEAD/commit, index/staging area, working tree) and tells you what is staged, what is modified-but-unstaged, and what is untracked.

**How the output is presented (OUTPUT section):** “The output from this command is designed to be used as a commit template comment. The default, long format, is designed to be human readable, verbose and descriptive. Its contents and format are subject to change at any time.” The manual also notes that, unlike many other Git commands, paths in the output are made **relative to the current directory** when you run it from a subdirectory (on purpose, to help with cutting and pasting; controlled by the `status.relativePaths` configuration) — machine-readable formats such as `--porcelain` are the stable, script-oriented alternative rather than the long format.
